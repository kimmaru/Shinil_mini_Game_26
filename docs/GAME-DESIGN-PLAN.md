# 완성 기획서 — 몸으로 놀자! 미니게임 파티 (2026-11-21)

이 문서는 "완성판"의 기준이다. 업계 전문가(WarioWare·Mario Party·EyeToy·Kinect
HIG·NN/g 아동 UX)가 이 장르를 기획하는 방식을 조사해서, 우리 제약에 맞게 숫자로
고정했다. 조사 출처는 각 항목 옆에 적었다. [권장]은 1차 자료가 없어서 업계 관행으로
정한 값이다.

## 0. 확정된 제품 조건

| 항목 | 값 |
|---|---|
| 플레이 환경 | MacBook Pro 2015 중기, macOS 12, Chrome, 내장 FaceTime HD 720p 캠 |
| 실행 | `npm run play` → 로컬 서버 + Chrome 앱 창. 외부 배포 없음 |
| 인원 | 1명 |
| 흐름 | 한 판씩: 대기 → START → 룰렛 → 설명+3·2·1 → 게임 → 결과 → 대기 |
| 게임 수 | 24종 (기존 22종 + 미완성 2종 `koko-ko-touch` `max-reach-stretch`) |
| 시각 방향 | 미니게임천국·마리오파티 계열의 밝은 캐주얼 파티. 아트는 전부 자체 벡터 |

## 1. 기획 원칙 (전문가 방식 → 우리 규칙)

1. **한눈에 이해.** WarioWare 디렉터의 유일한 규칙은 "무슨 일이 벌어지는지 즉시
   알 수 있어야 한다"였고, 기획서는 그림 한 장 + 단어 하나였다
   ([Iwata Asks](https://iwataasks.nintendo.com/interviews/wii/warioware_smooth_moves/0/2)).
   → 게임 1개 = 동작 1개. 설명은 `howToKo` 2줄 이내, 카운트다운에 **명령 단어 1개**
   ("짝!", "점프!", "뻗어!")를 크게.
2. **보면서 배운다.** Mario Party는 설명 화면에서 축소판을 연습시킨다.
   → 낯선 손님은 설명을 읽지 않으므로, 카운트다운 동안 **동작 데모 애니메이션**을 보여준다.
3. **내 몸이 화면에 있다.** EyeToy 팀은 "자기 모습이 보이는 것"이 접근성의 핵심이었다고
   회고한다([Game Developer](https://www.gamedeveloper.com/game-platforms/in-depth-eye-to-eye---the-history-of-eyetoy)).
   → 모든 게임·대기·카운트다운 화면에 스켈레톤을 항상 그린다. 사람을 놓치면 "화면 안에 서 줘!".
4. **몸 크기 공정성.** 목표 위치는 플레이어 자신의 보정값(어깨너비·팔길이) 기준.
   임계값은 어깨너비 단위(AGENTS.md).
5. **실패는 조용히, 성공은 크게.** 미스는 콤보만 끊는다. 하트 감소·빨간 X·큰 실패음 금지.
6. **난이도 곡선** [권장]: 처음 5초는 거의 무조건 성공, 중반 가속, 마지막 5초 피크.
7. **안전·피로**: 점프 ≤ 10회/판, 팔 머리 위 유지 ≤ 10초, 회전·바닥 접촉 없음.

## 2. 흐름 연출 스펙

| 단계 | 연출 | 시간 |
|---|---|---|
| 대기(attract) | 실제 게임이 합성 포즈로 돌아가는 배경 릴(3초마다 교체), 큰 로고, 펄스하는 START(1.2초 주기, 1→1.08), 내 스켈레톤 | 상시 |
| 룰렛 | 게임 8개 타일 위를 하이라이트가 돌다가 감속·정지. 칸마다 `ui.tick`, 마지막 3칸 간격 확대, 정지 직전 짧은 정적, 1.15배 팝 + 80ms 플래시 + `fanfare` | 3.5–4.5초, 건너뛰기 가능 |
| 설명+카운트다운 | 아이콘 + 게임 이름 slam-in, 명령 단어, 동작 데모 루프, 3·2·1 (숫자당 700ms, 1.6→1 스케일 + `count.beep`), "시작!" + `count.go` | 약 5–6초 |
| 게임 | HUD: 점수 알약, 남은 시간 링, 콤보. 마지막 5초 강조 | 30–60초 |
| 결과 | 별 1→3개 400ms 간격 오버슈트 등장(`star.1/2/3`), 점수 0→N 카운트업 1.2초, 오늘 최고 기록 배너, 3별/신기록이면 색종이 | 자동 복귀 20초 |

룰렛 결과는 애니메이션 시작 **전에** 정해진다(`decideRound`). 아이에게 "아깝게 놓침"
연출은 쓰지 않는다. 화면 효과 줄이기 모드에서는 0.45초 크로스페이드로 같은 결과를 보여준다.

## 3. 시각 언어 (캐주얼 파티)

- **배경**: 고채도 2–3색 그라데이션 + 천천히 흐르는 패턴(대각 줄무늬·물방울). 흰 단색 배경 금지.
- **글씨**: Pretendard 800–900, 흰 글자 + 짙은 외곽선(≈ 0.15 × 글자크기) + 아래 그림자 4–6px.
  반응해야 하는 글자 ≥ 34px.
- **형태**: 반경 24px 이상 라운드 사각형, 두꺼운 외곽선, 위쪽 하이라이트, 눌림 슬랩(6px).
- **모션**: 등장은 오버슈트 스프링(`--ease-out-back`), UI 등장 200–350ms, 정지 화면 없음(미세한 숨쉬기).
- **색 역할**: 강조 노랑·주황·핑크, 보상은 금색 별. 게임마다 고유 hue 1개(겹치지 않게 재배정).
- **아이콘**: 게임마다 전용 벡터 아이콘 `gi-<게임id>` (24종).
- 접근성 규칙(DESIGN.md §6: 대비, 포커스 링, 화면 효과 줄이기, 깜빡임 제한)은 그대로 유지.

## 4. 모션 입력 UX

- 지연 목표: 입력 → 첫 반응 100ms 이내(72%가 100ms 초과를 감지,
  [Kinect Joint Smoothing](https://learn.microsoft.com/en-us/previous-versions/windows/kinect-1.8/jj131429(v=ieb.10))).
  감지된 프레임에 바로 소리·파티클을 시작한다.
- 보정은 대기 화면에서 조용히. T자세 요구 없음.
- 사람이 6초 이상 없으면 대기 화면으로 복귀(`ABANDON_SEC`).
- 다리가 안 보이면 다리 필요 게임은 룰렛에서 빠진다(`lowerBodyVisible`).

## 5. 게임 품질 기준 (24종 모두)

AGENTS.md 금지사항 + 다음을 통과해야 `enabled: true`:
1. 스모크 테스트 전부 통과(8개 클립 생존, 자기 클립 득점, 가만히 서 있으면 무득점, 시드 결정성, 별 변별력).
2. 2초 안에 할 일이 보이는 화면(샷 PNG로 확인), 목표물 ≥ 화면 폭 8%.
3. 프레임당 그리기 ≤ ~250회, 파티클 상한, update/render 할당 0.
4. 한국어: 이름 ≤ 20자, 한 줄 소개 ≤ 18자, 설명 1–3줄 해요체.

## 6. 성능 예산 (2015 맥북)

- 렌더 ≥ 50fps, 포즈 추론 ≥ 20Hz. 캔버스 백스토어 DPR 상한(레티나 2배 그대로 그리지 않음).
- 모델은 `pose_landmarker_lite`, GPU 실패 시 CPU 자동 전환, 워밍업 실패는 치명적이지 않음.
- 대기 화면 배경 릴은 낮은 해상도·30fps, 게임 중에는 정지.

| 역할 | 모델 | 이유 |

## 8. 검증

`npx tsc --noEmit` · `npm run gate` · `npm run build` · 개인정보 검사 · 게임별 샷 PNG 확인 ·
브라우저에서 `?pose=virtual` 로 전체 흐름(대기→룰렛→카운트다운→게임→결과) 확인.
실제 맥북 카메라는 여기서 검증할 수 없으므로 첫 실행 체크리스트를 README에 남긴다.
